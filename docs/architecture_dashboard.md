## Overview

The Architecture Comparison Dashboard is an interactive web-based tool that visualizes and compares three different neural network architectures trained on the MNIST digit classification task:

1. **MLP (Multi-Layer Perceptron)**: 784 → 512 → 10, BLAS-accelerated dense layers
2. **CNN (Convolutional Neural Network)**: Conv(8,3×3) + MaxPool(2×2) + Dense(1568 → 10)
3. **Attention**: Transformer-style with patch embeddings, self-attention, and feed-forward networks

**Key Features:**
- **Side-by-side comparison**: Toggle models on/off to compare specific architectures
- **Multiple metrics**: Parameters, FLOPS, memory, accuracy, training time
- **Interactive charts**: Line charts for training curves, bar charts for resource comparisons
- **Layer-level analysis**: Detailed breakdown of parameter and FLOP counts per layer
- **Real training data**: Uses actual training logs from model runs
- **Zero dependencies**: Pure HTML/CSS/JavaScript with Chart.js for visualizations

**Use Cases:**
- **Educational**: Understand tradeoffs between different architectures
- **Research**: Benchmark new models against established baselines
- **Optimization**: Identify computational bottlenecks and efficiency opportunities
- **Presentations**: Generate publication-quality comparison visualizations

## Generating Dashboard Data

The dashboard displays data from `demo/dashboard_data.json`, which is generated by the `generate_dashboard_data` binary. This binary combines architecture metadata (computed by instantiating layers) with training metrics (parsed from CSV logs).

### Prerequisites

Before generating dashboard data, ensure you have:

**Required:**
- Rust toolchain (1.56 or later)
- `cargo` build system
- Trained models with CSV logs in `logs/` directory

**Optional (for viewing):**
- Python 3.x (for HTTP server)
- Modern web browser (Chrome, Firefox, Safari, Edge)

### Training Models

The dashboard data generator expects training logs in CSV format for each model/optimizer combination.

**Expected log files:**
- `logs/training_loss_mlp_<optimizer>.csv`
- `logs/training_loss_cnn_<optimizer>.csv`
- `logs/training_loss_attention_<optimizer>.csv`

Example (Adam):
- `logs/training_loss_mlp_adam.csv`
- `logs/training_loss_cnn_adam.csv`
- `logs/training_loss_attention_adam.csv`

**CSV format:**
```csv
epoch,train_loss,train_time,val_loss,val_accuracy,learning_rate
1,1.369,0.480,0.732,94.766,0.01
2,0.831,0.446,0.515,96.266,0.01
...
```

**Training commands:**

```bash
# Train MLP (10 epochs, ~5 minutes)
cargo run --release --bin mnist_mlp

# Train CNN (3 epochs, ~10 minutes)
cargo run --release --bin mnist_cnn

# Train Attention (8 epochs, ~15 minutes)
cargo run --release --bin mnist_attention_pool
```

Each training run automatically creates CSV logs in the `logs/` directory with per-epoch metrics.

### Running the Generator

Once training logs are available, generate the dashboard data:

```bash
# Standard generation
cargo run --release --bin generate_dashboard_data

# Generate dashboard data
cargo run --release --bin generate_dashboard_data

# Check what data is available without regenerating
ls -lh logs/*.{txt,csv}
```

**Output:**
```
Generating dashboard data...
  MNIST MLP — 407050 params, 813056 FLOPS, training data: YES
  MNIST CNN — 15850 params, 3156736 FLOPS, training data: YES
  MNIST Attention — 27738 params, 1269654 FLOPS, training data: YES

Dashboard data written to demo/dashboard_data.json
Open demo/architecture_dashboard.html in a browser to view.
```

### Output Files

**Generated file:**
- `demo/dashboard_data.json` - Complete dashboard dataset (~10-50KB depending on training epochs)

**File contents:**
- `generated_at`: ISO 8601 timestamp of generation
- `models[]`: Array of model data objects
  - `architecture`: Layer-by-layer parameter/FLOP counts
  - `training`: Per-epoch training metrics (if logs available)

**Note:** If training logs are missing for a model, the generator still includes architecture metrics but omits training data. The dashboard will display "N/A" for training-related fields.

## Viewing the Dashboard

The dashboard is a static HTML page (`demo/architecture_dashboard.html`) that loads data via JavaScript `fetch()`.

By default, it loads `demo/dashboard_data.json`.

You can also point it at *multiple* dashboard datasets using URL query parameters:

- `?models=<file1>,<file2>,...`
  - Example: `http://localhost:8080/architecture_dashboard.html?models=dashboard_data.json,other_run.json`
  - Each entry is fetched relative to the `demo/` directory.
- `?models_path=<dir>`
  - Example: `http://localhost:8080/architecture_dashboard.html?models_path=./runs/`
  - The dashboard will fetch `<dir>/index.json` to get a list of datasets, then fetch each listed JSON file.

The page must be served over HTTP (not `file://`) due to browser CORS restrictions.

## Dashboard Features

### Model Toggle Controls

**Location:** Top of dashboard, below the title

**Functionality:**
- Select which runs/models participate in the comparison using checkboxes
- Optionally **filter/group by architecture family** (based on `architecture.architecture_type` in the JSON)
- Convenience actions: **Select all** and **Clear**
- All charts and tables update instantly when selection changes

**Notes:**
- Colors are assigned per run and used consistently across charts
- Filtering by family disables (but does not delete) runs outside the selected families

**Use cases:**
- Compare two specific architectures by selecting only those runs
- Compare multiple runs of the same family (e.g., different optimizers)
- Focus on a single run for debugging/regression checks

### Summary Table

**Displays:**
- Model name with color-coded badge
- Total parameters (formatted: 407K, 1.2M, etc.)
- Total FLOPS for forward pass with batch size 1
- Memory usage in bytes (weights + biases)
- Best validation accuracy achieved during training
- Total training time across all epochs

**Sorting:**
- Rows appear in order: MLP, CNN, Attention
- Hover over rows for visual feedback

**Example:**

| Model | Parameters | FLOPS | Memory | Best Accuracy | Total Training Time |
|-------|-----------|-------|--------|---------------|-------------------|
| MNIST MLP | 407K | 813K | 1.6 MB | 97.95% | 4.7s |
| MNIST CNN | 15.9K | 3.2M | 63.4 KB | 98.50% | 8.2s |
| MNIST Attention | 27.7K | 1.3M | 110.9 KB | 90.12% | 12.5s |

### Training Curves

The dashboard shows two levels of training-curve visualization:

**Combined charts (overlay):**
- **Validation Accuracy**: line chart of `val_accuracy` vs. epoch (one line per selected run)
- **Loss**: line chart of `train_loss` (and `val_loss` if present) vs. epoch

**Side-by-side (small multiples):**
- A grid of per-run charts, useful when overlayed lines get cluttered
- Each run gets its own mini accuracy chart and mini loss chart

**Notes:**
- If a run has no validation metrics, the validation series is omitted and the table shows `N/A`.

### Performance Metrics

**Parameter Count (Bar Chart):**
- Horizontal bars showing total parameters per model
- Helps understand model size and memory requirements
- MLP typically has most parameters, CNN has fewest

**FLOPS Comparison (Bar Chart):**
- Horizontal bars showing computational cost
- FLOPS = Floating Point Operations for one forward pass
- CNN typically has most FLOPS despite fewer parameters

**Average Time per Epoch (Bar Chart):**
- Horizontal bars showing mean training time per epoch
- Computed from actual training logs
- Includes forward pass, backward pass, and parameter updates
- Does not include data loading or validation

### Layer Breakdown

**Displays:**
- Expandable section per active model
- Table with columns: Layer, Type, Params, FLOPS
- Total row summarizing parameter and FLOP counts

**Layer types:**
- **Dense**: Fully-connected layer (W*x + b)
- **Conv2D**: 2D convolution with learnable filters
- **MaxPool**: Max pooling (no parameters, no FLOPS counted)
- **Attention**: Q/K/V projections for self-attention
- **FFN**: Feed-forward network (two dense layers)
- **Linear**: Dense layer without activation

**Example (MLP):**

| Layer | Type | Params | FLOPS |
|-------|------|--------|-------|
| Dense 784 → 512 | Dense | 402K | 803K |
| Dense 512 → 10 | Dense | 5.1K | 10.2K |
| **Total** | | **407K** | **813K** |

## How It Works

### Architecture Overview

The dashboard is a client-side web application with three main components:

1. **Data Generator (Rust)**: `src/bin/generate_dashboard_data.rs`
   - Instantiates layer objects to compute parameter counts
   - Calculates FLOPS based on layer dimensions and batch size
   - Parses CSV training logs
   - Outputs `demo/dashboard_data.json`

2. **Dashboard HTML**: `demo/architecture_dashboard.html`
   - Single-page application (no backend required)
   - Loads JSON data via fetch API
   - Renders charts using Chart.js
   - Pure vanilla JavaScript (no frameworks)

3. **Training Scripts**: `mnist_mlp.rs`, `mnist_cnn.rs`, `mnist_attention_pool.rs`
   - Train models and write CSV logs to `logs/`
   - Logs include per-epoch metrics: loss, accuracy, time

### Data Flow

```
┌─────────────────────┐
│  Training Scripts   │
│  (mnist_mlp, etc.)  │
└──────────┬──────────┘
           │
           │ Writes CSV logs
           ▼
      ┌────────┐
      │ logs/  │
      └────┬───┘
           │
           │ Reads CSV logs
           ▼
┌──────────────────────┐
│ generate_dashboard_  │
│      data.rs         │
└──────────┬───────────┘
           │
           │ Writes JSON
           ▼
┌──────────────────────┐
│ demo/dashboard_      │
│      data.json       │
└──────────┬───────────┘
           │
           │ Fetch API
           ▼
┌──────────────────────┐
│ architecture_        │
│   dashboard.html     │
└──────────────────────┘
```

### Component Breakdown

**JavaScript State Management:**

```javascript
// Global state
let dashboardData = null;           // Parsed JSON data
const activeModels = new Set();     // Currently visible models
const modelColors = { ... };        // Color scheme per model

// Chart instances (Chart.js)
let accuracyChart, lossChart, paramsChart, flopsChart, timeChart;
```

**Initialization Flow:**

1. `DOMContentLoaded` event triggers `loadData()`
2. `loadData()` fetches `dashboard_data.json`
3. `init()` enables all models and creates Chart.js instances
4. `updateAll()` renders all charts and tables

**Update Flow (on toggle):**

1. User clicks model toggle
2. Event handler updates `activeModels` Set
3. `updateAll()` re-filters data and updates all visualizations
4. Chart.js handles animation and rendering

**Error Handling:**

- If `dashboard_data.json` is missing, displays error message with instructions
- If training data is missing for a model, displays "N/A" in affected fields
- Console warnings for invalid data formats (no user-visible errors)

```json
{
  "generated_at": "2026-02-18T05:24:33Z",
  "models": [
    { /* ModelData */ },
    { /* ModelData */ },

  ]

```

### Model Data Schema

**ModelData object:**

```json
{
  "id": "mnist_mlp",
  "name": "MNIST MLP",
  "description": "2-layer MLP (784 -> 512 -> 10) with BLAS-accelerated GEMM",
  "architecture": {
    "layers": [
      {
        "name": "Dense 784 -> 512",
        "type": "Dense",
        "params": 401920,
        "flops": 802816
      }
    ],
    "total_params": 407050,
    "total_flops": 813056,
    "memory_bytes": 1628200
  },
  "training": { /* TrainingData or null */ }
}
```

**Field descriptions:**
- `id`: Unique identifier (used for toggle state, CSS classes)
- `name`: Human-readable display name
- `description`: Architecture description shown in tooltips
- `architecture.layers[]`: Array of layer-level metrics
- `architecture.total_params`: Sum of all layer parameters
- `architecture.total_flops`: Sum of all layer FLOPS (forward pass, batch=1)
- `architecture.memory_bytes`: Total bytes for f32 weights and biases
- `training`: Training metrics (null if logs unavailable)

### Training Data Schema

**TrainingData object:**

```json
{
  "config": {
    "optimizer": "Adam",
    "lr": 0.001,
    "batch_size": 64
  },
  "epochs": [
    {
      "epoch": 1,
      "train_loss": 1.369,
      "val_loss": 0.732,
      "val_accuracy": 94.766,
      "train_time": 0.480,
      "lr": 0.01
    }
  ],
  "best_accuracy": 97.95,
  "total_time": 4.725
}
```

**Field descriptions:**
- `config.optimizer`: Optimizer name (SGD, Adam, AdamW, RMSprop)
- `config.lr`: Initial learning rate
- `config.batch_size`: Mini-batch size used during training
- `epochs[]`: Per-epoch metrics array
- `epochs[].epoch`: Epoch number (1-indexed)
- `epochs[].train_loss`: Cross-entropy loss on training set
- `epochs[].val_loss`: Cross-entropy loss on validation set
- `epochs[].val_accuracy`: Accuracy on validation set (0-100%)
- `epochs[].train_time`: Training time for this epoch (seconds)
- `epochs[].lr`: Learning rate at this epoch (may decay)
- `best_accuracy`: Highest validation accuracy across all epochs
- `total_time`: Sum of all epoch training times

## Understanding the Metrics

### Parameters

**Definition:** Total number of trainable weights and biases in the model.

**Calculation:**
- **Dense layer**: `(input_size + 1) × output_size`
  - Weights: `input_size × output_size`
  - Biases: `output_size`
- **Conv2D layer**: `(kernel_h × kernel_w × in_channels + 1) × out_channels`
  - Weights: `kernel_h × kernel_w × in_channels × out_channels`
  - Biases: `out_channels`

**Significance:**
- Directly correlates with model size (memory_bytes = params × 4 for f32)
- More parameters → greater capacity but higher risk of overfitting
- Attention has fewest parameters but complex computational graph

**Typical values (MNIST):**
- MLP: ~400K parameters
- CNN: ~15K parameters (fewer but more effective)
- Attention: ~27K parameters

### FLOPS

**Definition:** Floating Point Operations for one forward pass with batch size 1.

**Calculation:**
- **Matrix multiply (MxK @ KxN)**: `2 × M × K × N` operations
- **Dense layer forward pass**: `2 × batch × input × output`
- **Conv2D forward pass**: `2 × batch × out_h × out_w × kernel_h × kernel_w × in_ch × out_ch`

**Note:** FLOPS counts only multiply-add pairs. Does not include:
- Activation functions (ReLU, softmax)
- Bias additions (counted separately)
- Memory operations (loads/stores)
- Control flow overhead

**Significance:**
- Predicts computational cost and inference latency
- Hardware accelerators (GPUs, TPUs) excel at high-FLOP operations
- More FLOPS → longer training/inference time (roughly linear)

**Typical values (MNIST):**
- MLP: ~800K FLOPS (dominated by 784→512 layer)
- CNN: ~3.2M FLOPS (convolutions are expensive)
- Attention: ~1.3M FLOPS (self-attention over 49 tokens)

### Memory Usage

**Definition:** Bytes required to store all model parameters as f32 values.

**Calculation:** `memory_bytes = total_params × 4`

**Components:**
- Weights and biases only (stored parameters)
- Does not include:
  - Activations (forward pass intermediates)
  - Gradients (backward pass intermediates)
  - Optimizer state (Adam momentum, variance)

**Significance:**
- Determines model file size on disk
- Larger models take longer to load and serialize
- GPU memory usage is ~5-10× parameter memory (includes activations/gradients)

**Typical values (MNIST):**
- MLP: ~1.6 MB
- CNN: ~63 KB
- Attention: ~111 KB

### Training Time

**Definition:** Wall-clock time for forward pass, backward pass, and parameter update.

**Measured:** Per-epoch training time (averaged across batches)

**Factors affecting time:**
- FLOPS count (more operations = more time)
- Hardware (CPU vs GPU, BLAS implementation)
- Batch size (larger batches amortize fixed costs)
- Memory bandwidth (loading weights and activations)

**Not included:**
- Data loading time
- Validation pass time
- Logging/checkpointing overhead

**Typical values (MNIST, CPU):**
- MLP: ~0.45s per epoch
- CNN: ~2.5s per epoch (convolutions slower than dense)
- Attention: ~1.5s per epoch

## Troubleshooting

**Dashboard shows "Could not load dashboard_data.json"**

*Cause:* JSON file is missing or fetch failed (CORS issue).

*Solutions:*
1. Generate the data: `cargo run --release --bin generate_dashboard_data`
2. Ensure HTTP server is running (not `file://` protocol)
3. Check browser console for network errors (F12 → Console)
4. Verify `demo/dashboard_data.json` exists: `ls -lh demo/dashboard_data.json`

**Training data shows "N/A" for a model**

*Cause:* CSV log file is missing or has incorrect format.

*Solutions:*
1. Train the model: `cargo run --release --bin mnist_mlp` (or cnn, attention)
2. Verify log file exists:
   - MLP: `logs/training_loss_adam.txt`
   - CNN: `logs/training_loss_cnn.csv`
   - Attention: `logs/training_loss_attention.csv`
3. Check CSV format matches expected schema (epoch,train_loss,train_time,val_loss,val_accuracy,learning_rate)

**Charts not rendering**

*Cause:* Chart.js failed to load or JavaScript error.

*Solutions:*
1. Check browser console for errors (F12 → Console)
2. Verify internet connection (Chart.js loads from CDN)
3. Try a different browser (Chrome, Firefox, Safari)
4. Clear browser cache and reload (Ctrl+Shift+R / Cmd+Shift+R)

**FLOPS/parameter counts seem wrong**

*Cause:* Layer dimensions don't match actual training code.

*Solutions:*
1. Verify layer dimensions in `src/bin/generate_dashboard_data.rs` match training binaries
2. Check for changes in model architecture (e.g., different hidden sizes)
3. Regenerate data after architecture changes: `cargo run --release --bin generate_dashboard_data`

**Colors not displaying correctly**

*Cause:* Model ID mismatch or CSS variable error.

*Solutions:*
